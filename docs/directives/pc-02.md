## Goal
After this directive:
- nodes.toml accepts `push = "timer" | "container"` per node (default `timer`); another value is a
  registry error that `friday check`/`nodes --check` report.
- deploy/push.compose.yaml defines service `friday-push` using image `friday-dash:local` (built from
  deploy/Dockerfile when missing, the same build the dash uses; the Dockerfile gains `tmux` and
  `git` and stays multi-arch: no amd64-only URL or binary, packages from apt or a per-arch
  download keyed on `dpkg --print-architecture`). It runs `friday status --push --every 30` as the
  host user (`user: "${UID}:${GID}"`), `restart: unless-stopped`, `network_mode: host`, with:
  the node's repos dir read-only at the same absolute path, `~/.config/friday` read-only, the lease
  directory read-write, the tmux socket directory (`/tmp/tmux-${UID}`), `/proc` read-only at
  `/host/proc` (`FRIDAY_PROC_ROOT`), the repos dir as `FRIDAY_DISK_PATH`, `FRIDAY_PUSH_MODE=container`.
  GPUs: `friday nodes --setup` adds the compose GPU reservation only when `docker info` lists the
  `nvidia` runtime.
- `friday nodes --setup <node>` for a `container` node: confirms like today, builds the image on
  the node if missing, runs `docker compose -f <plugin_dir>/deploy/push.compose.yaml up -d`
  there, and disables and removes `friday-push.timer`/`.service` if they exist (and the reverse when
  a node goes back to `timer`: stop the container, install the timer). It never prunes images.
- `friday nodes --check` reports the push mode and, for `container`, whether the container is
  running, with the fix line.
- docs/fleet.md: when to choose each mode, what the container mounts and why, the arm64 note.

## Steps
1. lib/friday_fleet.py registry key and validation; bin/friday setup/check paths for both modes.
2. deploy/push.compose.yaml and deploy/Dockerfile (tmux, git, multi-arch).
3. docs/fleet.md, docs/spec.md (nodes.toml keys, `nodes --setup`/`--check`); tests/test_spec.py
   stays green. CHANGELOG `Unreleased` naming #13.
4. tests/test_push_container.py with fake ssh/docker/systemctl: setup for a container node runs
   compose up with the expected env and removes the timer; switching back stops the container and
   installs the timer; the GPU block only with an nvidia runtime; check reports a stopped
   container with the fix; the compose file's mounts, user, restart and command; the Dockerfile has
   no amd64-only reference; an invalid `push` value is an error.

## Out of scope
- Making the container the default, or removing the timer mode.
- Pruning or rebuilding images beyond building a missing one.
