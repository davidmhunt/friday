## Goal
`check_hardware` runs each pattern over the whole command line, so a script-path resource such as
`tools/console_switch\.sh` is "touched" by `git add tools/console_switch.sh`, `git diff ...` and a
commit message naming it, takes the lease and prompts (#32). After this directive:
- The hook matches hardware patterns per simple command (`fc.split_commands`), and skips simple
  commands that cannot run the device: `git` with subcommand `add`, `diff`, `log`, `status`,
  `show`, `blame`, `grep`, `rm`, `mv`, `restore`, `checkout`, `commit` (so the commit message is
  never matched). Every other simple command is matched as today, including `bash`, `sh`, `ssh`
  and anything running the script. Splitting is fail-closed: if the line cannot be split, the whole
  line is matched as today.
- `friday check` warns on a `hardware` pattern that matches `git add <x>` or `echo <x>` for a
  literal sample `<x>` taken from the pattern (best effort; no warning when no sample can be
  made), and the warning says how to anchor it on the command that runs it.
- `friday status` prints when each lease expires (`expires in N min`); the TTL is unchanged.
- The hardware skill and spec section on `hardware` show one script-path resource written so only
  an execution matches, including how to leave out a `--dry-run`.
