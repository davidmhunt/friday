## Goal
Agents never commit to Base (main stays protected), and pre-approval still works for goals on
main. Today the plan is committed on Base and `## Allowed commands` is read from `origin/<Base>`,
which an agent cannot push when Base is main. After this directive: the plan skill commits the
plan on `friday/<goal>` (created from Base) and pushes that branch; amendments are commits on the
goal branch too. The trusted copy for pre-approval is the ref `friday-plan/<goal>` on origin,
pushed only by `friday approve --goal <g>`, a user-only command (the hook denies it for agents in
every form, like `friday accept`) that runs `friday check --goal <g>`, refuses on errors or a dirty
tree, and pushes the goal branch's current plan commit to `friday-plan/<goal>`. The hook denies
any agent push to `friday-plan/*`. `check_preapproved` reads the directive and goal from
`origin/friday-plan/<goal>`; without that ref nothing is pre-approved (commands prompt as usual).
`friday start` still merges Base into the goal branch for upstream changes.

## Steps
1. bin/friday `friday approve --goal <g>`: check, clean-tree refusal (exit 8 like accept), push
   `friday/<g>` and `HEAD:refs/heads/friday-plan/<g>` (no force; a non-fast-forward is refused
   with a message), print what is now pre-approved. hooks/friday_hook.py: deny `friday approve`
   for agents in every form the accept guard covers; deny pushes whose destination is
   `friday-plan/*` (also in the deny list, so it holds between directives).
2. hooks/friday_hook.py `check_preapproved`: read from `origin/friday-plan/<goal>` (goal from the
   marker's directive on that ref, which must name the same goal); drop the origin/<Base> source
   and its Base checks. lib/friday_core.py: the commit-msg hook and `friday commits` keep treating
   plan-only commits on the goal branch as plan commits.
3. skills/plan/SKILL.md and skills/directive: commit the plan on `friday/<goal>` (never on Base),
   push it, and when any directive has `## Allowed commands` tell the user to run
   `! friday approve --goal <g>` (and again after an amendment). `/friday:execute` and dispatch
   unchanged except docs. docs/spec.md, docs/workflow.md, docs/fleet.md and docs/getting-started.md
   say where the plan lives and how approval is published; CHANGELOG `Unreleased`.
4. Tests: `friday approve` pushes both refs in a temp repo with a bare origin, refuses on check
   errors and a dirty tree; the hook denies `friday approve` from an agent (direct, `bash -c`,
   ssh) and `git push origin x:friday-plan/g`; pre-approval allows a listed command only when it
   is on `origin/friday-plan/<goal>`, not when it is only on the goal branch or Base.

## Out of scope
- GitHub branch protection settings (the user's choice per repo).
- Migrating goals already planned on Base (they keep working without pre-approval).
