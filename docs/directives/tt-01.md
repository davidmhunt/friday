## Goal
Today `check_push` in hooks/friday_hook.py denies every push while a directive is active unless it
updates only the goal branch, and it runs before pre-approval, so `git push origin
refs/tags/known-good/sar_uav-*` listed under `## Allowed commands` can never run. After this
directive: a `git push` whose every destination is an explicit tag ref (`refs/tags/<name>`, or the
`tag <name>` form) is allowed when the whole command is pre-approved by the active directive
(`check_preapproved`, read from `origin/<Base>` as today). Branch destinations stay limited to the
goal branch even when listed (tags cannot make Base a trusted source; branches could). `--tags`,
`--all`, `--mirror`, `--follow-tags` and an unjudgeable destination stay denied. Force (`+`,
`--force`, `-f`) stays denied by the deny list. `friday check` errors on an `## Allowed commands`
pattern that is a `git push` whose destination is not an explicit `refs/tags/` ref and not the
goal branch (`friday/<goal>`, or `friday/<id>` for `Land: pr`), naming why, so the plan is fixed
before approval.

## Steps
1. hooks/friday_hook.py: `_push_targets` keeps explicit tag refs as `refs/tags/<name>` (and maps
   `git push <remote> tag <name>` to `refs/tags/<name>`); `--tags` and `--follow-tags` make it
   unjudgeable. `check_push` allows a push whose destinations are all `refs/tags/*` only when
   `check_preapproved(cmd, cwd)` allows the command; otherwise the deny message says that a tag
   push needs a matching `## Allowed commands` entry on Base. Branch rules are unchanged.
2. lib/friday_core.py `validate_directive`: an Allowed commands pattern starting `git push` (also
   `git -C <dir> push`) whose destinations are not all `refs/tags/...` or the goal branch is an
   error ("the push guard denies this while the directive is active: only the goal branch and
   explicit refs/tags/ pushes"). A pattern whose destination is a bare `*` is an error too.
3. docs/spec.md (push guard row, Allowed commands rules, friday check list) and docs/fleet.md
   (Pre-approving commands) say a listed tag push runs and a listed branch push is a check error;
   tests/test_spec.py stays green. CHANGELOG `Unreleased` entry naming #24.
4. Tests (the existing push-guard test file, or a new tests/test_push_tags.py): a pre-approved
   `git push origin refs/tags/known-good/x` is allowed; the same not listed is denied with the
   new message; `git push origin tag known-good/x` listed is allowed; `--tags`, a `+refs/tags/x`
   force and a mixed tag+branch push are denied; a listed push to `main` stays denied; `friday
   check` errors on a listed `git push origin main` and `git push origin *` and accepts a listed
   tag push and goal-branch push.

## Out of scope
- Allowing pushes to any branch other than the goal branch.
- Tag pushes that are not listed in the directive.
