## Goal
tests/test_dash_docker.py builds the child PATH as `<fakes>/bin:<dirname(sys.executable)>`. When
the suite runs on the system Python that dirname is /usr/bin, which holds the real `docker` and
`gh`. On 2026-11-18 `test_up_without_docker_fails_clearly` (which deletes the fake docker) ran the
real `docker compose up` and recreated the laptop's live dash container with a pytest temp path as
its nodes.toml; after a reboot Docker recreated that path as a root-owned directory and every later
pytest run failed on `/tmp/pytest-of-david`. Seen 2026-11-20; the user approved this fix the same
day. After this directive no test puts a system bin directory on a child PATH: a test that needs
Python on PATH gets a private bin directory holding only a `python3`/`python` symlink to
`sys.executable` (plus its fakes), in tests/test_dash_docker.py, tests/test_cli_surface.py and any
other test found doing the same.

## Steps
1. A shared helper (tests/conftest.py or the existing helper module) that makes the private bin
   directory; tests/test_dash_docker.py and tests/test_cli_surface.py use it instead of
   `dirname(sys.executable)`. Grep tests/ for other child PATHs that include a system directory
   (`/usr/bin`, `/bin`, `dirname(sys.executable)`, `os.environ["PATH"]` appended after fakes in a
   test that deletes a fake) and fix those that could reach a real docker, gh, ssh or claude.
2. Regression test: with a sentinel `docker` placed next to a fake `sys.executable` directory
   (or by asserting on the PATH the helper builds), `friday dash up` with the fake docker deleted
   reports "docker is not installed" and no directory on the child PATH contains a real `docker`
   or `gh`.

## Out of scope
- Changing `friday dash up` itself.
- Recreating the live dash container (done by hand after the merge).
