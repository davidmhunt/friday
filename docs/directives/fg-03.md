## Goal
After this directive, when `forge()` is `gitlab`, `friday land --goal <g>` (goal `Land: pr`) and
`friday land <id>` (directive `Land: pr`) take the same steps as on GitHub, with glab
(`FRIDAY_GLAB` overrides the binary, like `FRIDAY_GH`):
- not installed or not signed in for the host (`glab auth status --hostname <host>` fails): exit 5,
  `MR not opened: ...` and the COMPARE line, as the GitHub path does;
- an open MR from the branch already exists (`glab mr list --source-branch <head> --output json`
  or `glab mr view <head>`): print `PR: <web_url>` and exit 0;
- else `glab mr create --source-branch <head> --target-branch <Base> --title <goal title>
  --description <same body the GitHub PR gets> --yes`, with `-R <host>/<slug>` (or `GITLAB_HOST`
  set) so it never depends on the cwd's glab config; print `PR: <url>`. The `PR:` prefix stays,
  so the workflow and dash parse it unchanged.
Exit codes match the GitHub path; the body is passed by file or stdin, never argv text that could
break on quotes.

## Steps
1. bin/friday: a small forge layer (`_open_change_request(forge, ...)`) used by `cmd_land` and
   `land_goal`; the GitHub branch keeps its current calls.
2. docs/spec.md (`friday land`, exit codes, landing section: GitHub PRs or GitLab MRs);
   tests/test_spec.py stays green. CHANGELOG.
3. tests/test_land_gitlab.py with a fake glab that logs argv: create with the right branches,
   title and body; existing MR found and not duplicated; not signed in gives exit 5 with the
   compare URL; a self-hosted host and nested group reach glab as `-R`; gh is never called.

## Out of scope
- Approving or merging MRs; GitLab CI status.
