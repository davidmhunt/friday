## Goal
With `"bash_file_io": "deny"`, the workflow's Verify run of a line such as `test -s docs/x.md &&
grep -q '^## Verdict' docs/x.md && ./run ...` is denied by the hook, and the directive blocks with
`Verify not run: no reason given` (#33, fmcw3-ckflight fnd-05). Verify is a gate, not agent file
I/O. After this directive:
- `check_bash_file_io` returns no decision for a command that equals the active directive's
  `Verify:` line (marker present; compared after stripping surrounding whitespace). Only the
  bash_file_io rule is skipped: the deny list, run_only, push, hardware and every other check
  still apply to that line.
- The Verify prompt in workflows/execute.js tells the runner to put the denial or error text in
  `not_run_reason` verbatim when the call is denied; when the result has no reason the block says
  `Verify not run: the Verify call returned no reason (check the hook output)` rather than
  "no reason given".

## Steps
1. hooks/friday_hook.py `check_bash_file_io` exemption.
2. workflows/execute.js Verify prompt and the fallback text.
3. docs/spec.md (bash_file_io row, Verify phase); tests/test_spec.py stays green. CHANGELOG
   `Unreleased` naming #33.
4. Tests: the #33 Verify line with the marker set is not denied by bash_file_io; the same line with
   another directive's marker, or with a byte changed, is; a Verify line that matches the deny list
   is still denied; the execute.js test checks the prompt and the fallback text.

## Out of scope
- Running Verify through `friday verify` (it would hide the line from the hook's other checks).
