## Goal
Today `friday start <id>` reads the directive from the working tree before it merges Base, so a
directive added on Base fails with `friday: no directive docs/directives/<id>.md` until someone
merges by hand, and that merge conflicts on the goal file's `Status:` line (Base `approved`, goal
branch `running` or `done`). After this directive: when the directive is missing on the current
branch, `friday start` looks for it on the goal branch, then on Base (`origin/<Base>` after the
fetch, else local Base); if found there it prints `found <id> on <ref>: merging <Base> into
friday/<goal>`, switches to the goal branch (creating it from Base if needed), merges Base, and
then resolves and checks the directive as today. During any Base merge `friday start` makes, a
conflict confined to the `Status:` lines of goal and directive files is resolved in favour of the
goal branch (lifecycle state lives there; the body comes from Base); any other conflict aborts the
merge and exits with the conflicted paths, as today. A goal whose `Status:` is `done` on the goal
branch but which now lists a directive that is not done is set back to `running` by `friday start`
(in the same merge commit or a plan-only commit), so a goal amended after its PR opened can run
its new directives.

## Steps
1. bin/friday `cmd_start`: before `_need`, if the directive file is absent, find it on
   `friday/<goal>` or Base by scanning `git show <ref>:docs/directives/<id>.md`; the goal comes
   from that copy's `Goal:` line. Switch and merge as described, then continue with the normal
   checks on the merged tree. Not found anywhere keeps today's message, naming where it looked.
2. The merge helper used by `friday start` (lib/friday_core.py): on conflict, if every conflicted
   file is a `docs/goals/*.md` or `docs/directives/*.md` whose only conflicting hunks are
   `Status:` lines, take the goal-branch side for those lines, keep both sides elsewhere, and
   commit; otherwise `git merge --abort` and refuse as today. A `done` goal with an undone listed
   directive becomes `running`.
3. docs/spec.md (`friday start` row and the amendment paragraph in section 6), docs/workflow.md
   where amendments are described; tests/test_spec.py stays green. CHANGELOG `Unreleased` naming #25.
4. Tests in a temp repo with an origin: a directive committed only on Base starts (merge happens,
   message printed, branch has the file); a Status-only conflict on the goal file resolves to the
   goal branch's value; a conflict in a step line aborts and names the file; a `done` goal with a
   new approved directive starts it and the goal reads `running`.

## Out of scope
- Resolving conflicts outside `Status:` lines automatically.
