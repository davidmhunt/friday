# gm-03: `/friday:execute` on the goal model: parse-driven Prepare, Acceptance review, land by field
Status: approved
Goal: goal-model
Node: any
Deliverable: code
Land: goal
Verify: uv run --with pytest pytest -q && claude plugin validate . && ./bin/friday check --all
Hardware: none

## Goal
`workflows/execute.js` reads the directive through `friday parse --json` instead of a model
reading markdown, works on the goal branch in goal order, skips Verify for external deliverables,
has the verifier grade `## Acceptance`, and lands by the Land field, opening the goal's single PR
after its last directive. A node test runs the script with a stubbed `agent()` and checks each
branch without network.

## Steps
1. Prepare: a `friday:runner` agent runs `friday parse <id> --json` and returns its exit code and
   stdout verbatim (schema `{exit_code, stdout}`); the script `JSON.parse`s it. On exit != 0, bad
   JSON, errors, or Status not `approved`/`running@...`: return `<id> not started: <errors>`. Then
   an implementer runs `friday start <id> --no-gate` (which switches branch and enforces order),
   records `git rev-parse HEAD` as the review base, and commits the directive (last line
   `Directive: <id>`); if start refuses, return its output. Use the parsed steps, verify,
   deliverable, land, goal, acceptance, position and goal_directives from then on.
2. Verify: for Deliverable `external`, skip the phase and log why. Review: pass the Acceptance
   bullets to the verifier; extend the REVIEW schema with `acceptance: [{item, met, evidence}]`;
   every unmet item counts as a gap. Review diffs are `<review base>..HEAD` (this directive's
   commits only). Update `agents/verifier.md` to say it grades `## Acceptance` and, for doc and
   slides, checks the built output named in the Log.
3. Land by field. All: Log entry (commits, Verify result or `Verify: n/a (external)`, and the line
   `Independent review: <verdict>`), `friday finish <id>`, commit. Then `goal` -> run `friday land
   <id>` (pushes the goal branch); if position equals the number of goal directives, run
   `friday land --goal <goal>`. `pr` -> `friday land <id>`. `none` -> no push. The final message
   says which happened: "committed only", "pushed friday/<goal>; next: /friday:execute <next id>",
   or the PR / compare URL, using the 0/3/4/5/6 meanings.
4. Update `meta` (description and phases) to the goal model. After Prepare, log the step list:
   `log(\`${id}: ${d.steps.map(s => \`${s.n}. ${s.text.slice(0, 60)}\`).join(' | ')}\`)`, and label
   each implement agent `step ${s.n}/${d.steps.length}` (plus ` [heavy]`). In `agents/verifier.md`
   and the review prompts, the trailer rule is: every commit message contains the line
   `Directive: <id>`, before or after a `Co-Authored-By` trailer (not necessarily last).
5. Tests in `tests/test_friday.py` (skipped when `node` is missing): load `workflows/execute.js`,
   strip `export ` from the meta line, wrap the body in an async function of `(args, agent, phase,
   log)` and run it in `node` with a stub `agent()` that returns canned results by label and
   records every prompt. Cases: parse errors stop before start; start refusal stops; external
   skips Verify; an unmet Acceptance item triggers the fix round; Land goal mid-goal pushes only;
   Land goal on the last directive also runs `friday land --goal`; Land pr runs `friday land <id>`;
   Land none runs no land command; the final message for each.

## Out of scope
- Running directives of one goal in parallel.
- Dispatch (`FRIDAY_DISPATCHED_FROM`, fleet-02).
- Skill and docs prose (gm-04).
