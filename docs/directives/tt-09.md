## Goal
On Ubuntu 22.04 nodes (system Python 3.10, e.g. a Jetson) friday fails with `No module named
'tomllib'`. The user chose to run every friday Python entry point on a uv-managed interpreter
(2026-11-19: "Full uv, hooks too"). After this directive:
- `friday install` runs `uv python install 3.12` if needed, records the path from
  `uv python find 3.12` in `~/.local/state/friday/python`, and writes `~/.local/bin/friday` as a
  small sh shim that execs that interpreter on `<plugin_dir>/bin/friday` (replacing the symlink;
  an old friday symlink is repointed, a foreign file is still refused).
- `bin/friday-python` (POSIX sh, in the plugin) resolves the interpreter: the recorded path if it
  exists and runs; else `uv python find 3.12`; else, as a last resort so the safety hooks never
  silently stop, `python3` with a one-line warning on stderr naming the fix (`friday install`).
  hooks/hooks.json runs every hook as `"${CLAUDE_PLUGIN_ROOT}/bin/friday-python"
  "${CLAUDE_PLUGIN_ROOT}/hooks/friday_hook.py" <event>`. The launcher adds no uv call on the hot
  path when the recorded path exists (one file read and an exec).
- Remote snippets in bin/friday and lib/friday_fleet.py (`setup_install`, `_SETUP_PY`,
  `_NODEFILE_PY`, `_TIMER_PY`, the trust, settings and reads probes, dispatch scripts) run through
  the node's `<plugin_dir>/bin/friday-python`, never bare `python3`.
- `import tomllib` falls back to `tomli` when missing (belt and braces for the last-resort path).
- `friday nodes --check` reports uv, the recorded interpreter and its version per node, with the
  fixes `uv python install 3.12` and `friday install`; `friday status` warns locally when hooks
  would fall back to the system `python3`.
- No `pyproject.toml`: with one, `uv run` in the plugin directory builds a project `.venv` and
  hides the system packages the test suite uses; the Python requirement is stated in the docs.

## Steps
1. bin/friday-python launcher and `friday install`/`friday uninstall` (shim, recorded path, uv
   steps; uninstall removes the shim and the record); `_is_friday_link` recognises the old
   symlink and the new shim. lib/friday_fleet.py tomllib fallback.
2. hooks/hooks.json uses the launcher for every hook; a test runs the launcher with a fake
   recorded path, with none (uv on a fake PATH), and with neither (python3 fallback + warning).
3. Remote snippets use `<plugin_dir>/bin/friday-python`; `nodes --check` probes uv and the
   recorded interpreter (`<path> -c 'import sys; print(sys.version_info[:2])'`) with fix lines;
   `nodes --setup` runs `uv python install 3.12` via `friday install` on the node; `friday status`
   warning.
4. docs/getting-started.md (install: uv is now required; `friday install` sets up Python),
   docs/fleet.md (node prerequisites), docs/spec.md (install, hooks, config/state files,
   `nodes --check`); tests/test_spec.py stays green. CHANGELOG `Unreleased` naming #29.
5. Tests: install writes the shim and record in a temp HOME with a fake `uv` on PATH; reinstall
   over an old symlink repoints it; a foreign file is refused; uninstall removes both; probe
   script contains no bare `python3 -c`; check reports a 3.10-only node with the fix lines; the
   CLI imports under the tomli fallback (simulate a missing tomllib).

## Out of scope
- Adding third-party dependencies to friday.
- Changing how projects run their own Python (`./run`, `uv run` in Verify).
