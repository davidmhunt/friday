## Goal
`check_preapproved` returns None silently when `origin/friday-plan/<goal>` is missing, so a goal
whose plan was never published runs with nothing pre-approved and nobody is told (#31: nine
directives in console, constant prompts). After this directive a plan's publish state is one of
`published` (the ref's copy of the directive's `## Allowed commands` equals the working tree's),
`not published` (no ref) or `stale` (the lists differ), computed by one function in
lib/friday_core.py, and:
- `friday start <id>`, for a directive with `## Allowed commands` that is not `published`, prints
  one line: `Allowed commands are NOT pre-approved (<state>): the user runs "! friday approve
  --goal <g>"` (on stdout, exit unchanged).
- `friday status` shows `plan: published | not published | stale` per running goal whose
  directives have Allowed commands (and `--json` carries it).
- The execute workflow's Prepare phase passes that line to the user (in the workflow's progress
  output, before Implement) without blocking.
- The PreToolUse hook: when a command matches the working tree's `## Allowed commands` of the
  active directive but the plan is not `published`, the `ask` it falls through to (or a new `ask`
  if none) carries the reason and the one command the user runs.
- Migration: a goal approved under the old flow whose `friday/<goal>` branch does not exist yet:
  the user's publish command explains how to create the branch from Base first (or does it when
  run on Base with `--goal`), and CHANGELOG `Unreleased` says so.

## Steps
1. lib/friday_core.py: `plan_publish_state(root, did)`; bin/friday `cmd_start` line and
   `cmd_status` (text and `--json`).
2. hooks/friday_hook.py: the ask reason in `pretool`/`check_preapproved` as above (never an
   allow).
3. workflows/execute.js Prepare: relay the start line; the user's publish command's migration path.
4. docs/spec.md (start, status, hook table, pre-approval section), skills/plan/SKILL.md if it
   names the publish step; tests/test_spec.py stays green. CHANGELOG `Unreleased` naming #31.
5. Tests: the three states; start prints the line only when not published; status text and json;
   the hook's ask names the command and never allows; the workflow test sees the relayed line.

## Out of scope
- Pre-approving anything without the published ref.
