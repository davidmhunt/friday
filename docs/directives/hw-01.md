## Goal
The hardware prompt states plainly that the lease lasts the session but the approval is for this
command only (unless pre-approved or the resource is session-approved). A resource marked
`"session"` under `hardware_approval` in `.claude/friday.json` is approved once: after the user
lets one matching command run, later matching commands in the same session (and its subagents)
are allowed while that session holds the lease. Agents are told to write one simple command per
hardware query so pre-approval applies. tests/test_hardware_session.py proves it.

## Steps
1. Wording (hooks/friday_hook.py `check_hardware`): the ask reason says the lease is held for this
   session and this approval covers this command only; when the resource is session-approvable it
   adds that approving it once approves the rest of the session.
2. Config: optional `hardware_approval` map in `.claude/friday.json`, values `command` (default) or
   `session`; `friday check`/`load_config` reject other values and unknown resources.
3. Session approval: register PostToolUse for `Bash` too (hooks/hooks.json). When a command that
   matched a `session` resource has run (PostToolUse fires only after the user allowed it), record
   `approved: true` on that resource's lease for that session. PreToolUse: a matching command on a
   resource whose lease this session holds with `approved: true` gets `allow` with the reason
   `<resource> approved for this session`. Deny list, accept rule and the other-session lease deny
   still win. The approval ends with the lease (`friday release`, TTL, session end). Confirm in the
   Claude Code hooks docs that subagents share the session id, and record it in
   `runs/hw-01/notes.md`; if they do not, say so in the docs instead of claiming subagent coverage.
4. Guidance: skills/hardware/SKILL.md, agents/implementer.md and agents/runner.md: one simple
   command per hardware query (`git -C DIR` rather than `cd DIR &&`, `ssh host cmd > local.txt`
   then process locally), so `## Allowed commands` and session approval apply. docs/spec.md:
   `hardware_approval`, the new reasons, and that pre-approval matches one simple command.
5. tests/test_hardware_session.py: default resource asks every time with the new wording; a
   session resource asks once, then allows after a PostToolUse for that session; another session
   still asks or is denied while the lease is held elsewhere; release ends the approval; a bad
   `hardware_approval` value fails `friday check`. CHANGELOG (1.1.0 section) naming #15.

## Out of scope
- Allowing chained remote commands (`ssh host 'a && b'`) under pre-approval.
- Any approval that outlives the session's lease.
