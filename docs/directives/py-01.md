## Goal
Today `friday install` runs `uv python install 3.12` into uv's default directory. That writes
`~/.local/bin/python3.12` (ahead of /usr/bin on PATH) and makes every `uv run` without a pinned
Python, in any repo, pick the managed 3.12, which lacks system packages (yaml, ROS). Seen on the
laptop, Alfred and sar_uav on 2026-11-19: friday's own suite failed with `No module named 'yaml'`.
The user wants the uv-managed interpreter to be the one friday uses, not the system Python, without
that side effect (2026-11-19: "can we correct this so that the uv managed environment is the one
used by friday instead of the system python?"). After this directive:
- `friday install` installs into a friday-private directory,
  `${XDG_DATA_HOME:-~/.local/share}/friday/python`, with `uv python install 3.12 --no-bin
  --install-dir <dir>` and finds it with `UV_PYTHON_INSTALL_DIR=<dir> uv python find
  --managed-python 3.12`. It refuses to record a path outside that directory. It writes nothing to
  ~/.local/bin except the friday shim, and leaves uv's default install directory alone.
- bin/friday-python's uv fallback looks only in that directory (same env and `--managed-python`),
  never at uv's default or system interpreters; the python3 last resort and its warning stay.
- Remote setup and `nodes --check` fix lines name `friday install` (which does the private install),
  not a bare `uv python install 3.12`.
- `friday uninstall` also removes the private directory.
- The suite declares its third-party test dependency: the Default Verify and the test commands in
  CLAUDE.md and docs use `uv run --with pytest --with pyyaml`, so the tests pass on any interpreter.
- docs/getting-started.md says how to undo the side effect of a 1.2 pre-release install (remove
  `~/.local/bin/python3.12` if it links into uv's directory, `uv python uninstall 3.12` if nothing
  else uses it, then `friday install`).

- Pinning the Python friday's own tests run on.
