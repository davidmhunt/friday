## Goal
`workflows/execute.js` makes no bookkeeping commits of its own: steps commit only tracked-file
changes, Verify and Review results are passed to one `friday finish` call (gm-05), and a
simulated 3-step run where one step only measures yields exactly 2 commits. Progress labels show
where a run is. The docs state the commit rules, the squash-merge recommendation and the
parallelism decision.

## Steps
1. Prepare: the start agent runs `friday start <id> --no-gate` and returns `review_base` from its
   `base <sha>` line; it commits nothing. Update the Prepare phase detail in `meta`.
2. Implement: each step brief says "Commit only if you changed tracked files (last line
   `Directive: <id>`); if the step only reproduces, measures or inspects, append your findings to
   `runs/<id>/notes.md` and do not commit." Fix briefs (verify and review) keep "commit".
   Relabel verify fix rounds `fix ${round}/${MAX_FIX_ROUNDS}` (prefixed `after review ` for the
   second loop); keep the step-list log and `step ${n}/${total}` (plus ` [heavy]`) labels.
3. Land and block: the finish agent runs exactly `friday finish <id> --verify "<verifyLine>"
   --review "<verdict>"` (verdict `no gaps`, or the gaps fixed in the second review) and returns
   its exit code and output; it writes no Log text and makes no commit itself. `block()` runs
   `friday finish <id> --blocked "<reason>"` with the Verify/review state known so far. Then
   push/PR by the Land field as now.
4. Tests in `tests/test_friday.py` (skipped without `node`): update existing execute.js cases for
   the new prompts and labels; add a case where the fake `agent()` acts on a real temp git repo
   with a goal and a 3-step directive: start runs the real `friday start`, step 1 and step 3 are
   simulated (step 1 commits a code change, step 2 only appends to `runs/<id>/notes.md`, step 3
   changes nothing tracked), verify/review pass, finish runs the real `friday finish`. Assert
   `git log <base>..HEAD` has exactly 2 commits (1 code + `<id>: record results`), both with the
   trailer, and the Log entry contains the notes. Also assert fix labels `fix 1/4`.
5. Docs: `docs/workflow.md` and `CHANGELOG.md`: the commit rules (gm-05 and this directive) and a
   recommendation to make squash-merge each repo's default merge method on GitHub (one commit per
   goal on the base; the branch keeps the detail), with the command
   `gh repo edit --enable-squash-merge --enable-merge-commit=false --enable-rebase-merge=false`
   or Settings -> General -> Pull Requests. `docs/HANDOFF.md`: section 2 decision row "Steps and
   directives within a goal run sequentially for now; parallelism is across goals (separate
   branches/worktrees/machines)"; section 5: phase 3 dispatches whole goals
   (`friday dispatch --goal <g>`): one machine runs a goal's directives in order and opens its
   one PR; section 7: keep the parallel-directives-as-sub-branches follow-up and add
   "plan-time warning when two active goals expect to touch the same files" and "multi-angle
   review (parallel read-only verifiers) in execute.js".
