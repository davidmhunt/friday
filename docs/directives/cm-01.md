# cm-01: A commit already on the goal branch when a directive starts is not reported as its untracked work (fixes #30)

Hardware: none

## Goal
`friday commits <id>` measures from the goal's Base, so commits that reached the goal branch through
an earlier directive's merge of a non-Base branch (no `Directive:` line on them) are `untracked` for
every later directive, and the reviewer counts each as a gap (seen in console goal align-code). After
this directive, in `lib/friday_core.py` `directive_commits`:
- an untrailered commit that is an ancestor of the HEAD in `runs/<id>/start` is dropped (it was on the
  branch when the directive started);
- the second-parent history of a merge whose message has a `Directive:` line naming a different
  directive is excluded, like a Base merge (that directive's review covered it), so the fix also
  holds when `runs/<id>/start` is absent;
- an untrailered commit made after start, and a merge trailed with this directive's own id, still
  show as before.

## Steps
1. lib/friday_core.py `directive_commits` as above; update its docstring.
2. docs/spec.md section 6 "A directive's change set": say which commits are dropped and why;
   tests/test_spec.py stays green. CHANGELOG `Unreleased` line naming #30.
3. Tests in tests/test_directive_commits.py: directive A merges a side branch (merge trailed
   `Directive: A`, side commits untrailered) and makes an untrailered hand commit; B starts and makes
   one trailed commit: `friday commits B` lists B's commit and no untracked lines. Same with
   `runs/B/start` removed: the merged side commits are still not listed. An untrailered commit made
   after B's start is still untracked. A side-branch merge trailed `Directive: B` still lists its
   untrailered commits for B.
