# tt-07: Opt-in `bash_file_io: "deny"` hook rule sends file reads and writes to the file tools; `run_only` ignores quoted text (fixes #27)
Status: approved
Goal: thin-targets
Node: any
Deliverable: code
Land: goal
Verify: uv run --with pytest pytest -q tests/test_docs.py tests/test_spec.py && uv run --with pytest pytest -q && claude plugin validate .
Hardware: none

## Goal
In an unattended run every Bash file read or edit that is not pre-approved is a prompt nobody
answers. With `"bash_file_io": "deny"` in `.claude/friday.json`, the PreToolUse hook denies (does
not ask) Bash commands that do file I/O the file tools cover, with the reason "use Read/Grep/Glob
for reading and Edit/Write for writing files; Bash is for running programs". Denied: `cat`,
`head`, `tail`, `less`, `more`, `sed`, `awk`, `grep`, `egrep` and `rg` when they have a file
operand (not when they only read a pipe), `sed -i`, `tee <file>`, a heredoc (`<<`), a `>`/`>>` redirect
to anything but `/dev/null` or a `/dev/fd`/`&N` target, and `python3 -`/`python -` or
`python3 <<` fed on stdin. Allowed: those tools at the end of a pipeline reading stdin
(`cmd 2>&1 | tail -3`, `git log | head`), `2>&1`, commands not in the list. Default (key absent
or `"allow"`) changes nothing. Separately, `check_run_only` (and any rule using
`fc.split_commands`) no longer matches words inside quoted arguments: `gh issue create --body
"... python3 - ..."` is not treated as running python3. Rules that must see inside quotes on
purpose (the deny list, the accept guard) keep doing so.

## Steps
1. hooks/friday_hook.py: `check_bash_file_io(cmd, cfg)` run in `pretool` after the deny list and
   before pre-approval (a listed command is still denied: the point is feedback, not a prompt),
   only when `cfg.get("bash_file_io") == "deny"`; uses `fc.split_commands`/`fc.argv_of` and
   knows pipeline position (a tool reading stdin is allowed). lib/friday_core.py `load_config`
   accepts `bash_file_io` (`deny` or `allow`; another value is a `friday check` error).
2. lib/friday_core.py `split_commands`: make it quote-aware (do not split on `;`, `&&`, `|`,
   newlines inside single or double quotes) if it is not already, and check `check_run_only`
   against a quoted-argument case; fix whichever is the cause of the #27 side note.
3. docs/spec.md (hook table, config table), agents/implementer.md and agents/runner.md (say the
   file tools are preferred and the rule may deny), `friday init` prints the key as an option;
   tests/test_spec.py stays green. CHANGELOG `Unreleased` naming #27.
4. Tests (tests/test_bash_file_io.py): at least 20 cases: denied `cat notes.md`, `sed -n 1,60p
   f`, `grep -n x file`, `tail -n +1 runs/*/*.txt`, `printf x >> notes.md`, `sed -i`, `tee f`,
   heredoc, `python3 - <<`; allowed `cmd 2>&1 | tail -3`, `git log | head -5`, `ls runs`,
   `uv run pytest -q > /dev/null`, `echo hi` (no redirect); key absent allows all; `allow`
   allows all; the deny reason names the file tools. run_only: `gh issue create --body "use
   python3 - here"` with python3 in run_only is not denied, `python3 x.py` still is.

## Out of scope
- Making `bash_file_io` the default.
- Classifying remote (ssh) commands.
