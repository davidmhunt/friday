# tt-08: Verify runs as one plain foreground call, and a Verify that was never run is reported as such, not as a failure (fixes #28)
Status: approved
Goal: thin-targets
Node: any
Deliverable: code
Land: goal
Verify: uv run --with pytest pytest -q tests/test_docs.py tests/test_spec.py && uv run --with pytest pytest -q && claude plugin validate .
Hardware: none

## Goal
Today the Verify prompt in workflows/execute.js says the command "can take several minutes", so
the `friday:runner` agent sometimes starts it detached (`setsid nohup ... &`). Auto mode denies
that, or the detached run is killed, and the result is reported as "Verify still fails after N
round(s)" although Verify never ran; the fix rounds then burn agents fixing nothing (seen in the
console repo and in this goal's tt-04). After this directive the Verify prompt tells the runner to
run the command as ONE plain foreground Bash call with a 600000 ms timeout (no `setsid`, `nohup`,
`&`, `run_in_background`, or detached job), and drops the "several minutes" hint. The VERIFY
schema gains `ran: boolean` (false when the call was denied, timed out before finishing, or was
never made) and `not_run_reason`. When `ran` is false the workflow blocks at once with
`Verify not run: <reason>` and runs no fix rounds. agents/runner.md says a Verify command is
always foreground; the long-jobs pattern applies only to work a step names as long.

## Steps
1. workflows/execute.js: the Verify prompt and schema as above; `verifyLoop` blocks on `ran ===
   false` before any fix round, with the reason in the block text; a timeout past the Bash limit
   counts as not run and says to raise the timeout or narrow Verify.
2. agents/runner.md and skills/long-jobs: a Verify command is one foreground call; detaching is
   for long runs a step names, never for Verify.
3. docs/spec.md (execute workflow, Verify phase) and docs/workflow.md where Verify is described;
   tests/test_spec.py stays green. CHANGELOG `Unreleased` naming #28.
4. Tests (the existing execute.js tests): the Verify prompt contains "one plain foreground" and no
   "several minutes"; a `ran: false` result blocks with "Verify not run" and starts no fix agent; a
   failing `ran: true` result still gets fix rounds.

## Out of scope
- A `Verify-long` header (Verify stays cheap; long work goes through `friday result`).
