# gm-05: Lean bookkeeping in the CLI: `start` commits nothing, `finish` writes the record in one commit
Status: approved
Goal: goal-model
Node: any
Deliverable: code
Land: goal
Verify: uv run --with pytest pytest -q && claude plugin validate . && ./bin/friday check --all
Hardware: none

## Goal
A directive adds exactly one bookkeeping commit to its branch: the record that `friday finish`
writes at the end. `friday start` changes no tracked file except the goal's first
`approved -> running` flip, which that one finish commit carries. Steps that only reproduce,
measure or inspect write findings to the untracked `runs/<id>/notes.md` and commit nothing.
bench-01 had 6 commits for one code change; under these rules it has 2.

## Steps
1. `friday start <id>` (`bin/friday`): stop calling `fc.set_status` on the directive; the
   directive file keeps `Status: approved` while it runs. Keep the goal file's
   `approved -> running` edit, uncommitted. Store `base` (`git rev-parse HEAD` after the branch
   switch) in the local marker next to id/host/started/gate, and print `base <sha>`. Warn on
   stderr when `runs/` is not gitignored (`git check-ignore -q runs/<id>/notes.md` fails),
   naming the `.gitignore` line to add. Allow re-starting a directive whose marker already exists
   (keep the stored base).
2. `friday status`: show a directive as `running@<host>` when the marker here names it, whatever
   its file says; keep the `active here:` line and add the base. Old `running@<host>` values in
   files still validate (parser and validator unchanged).
3. `friday finish <id> [--verify TEXT] [--review TEXT] [--base SHA] [--blocked REASON]`:
   refuse (exit 1, list the files) when tracked files other than this directive's file and its
   goal file have uncommitted changes. Base: `--base`, else the marker's base, else refuse.
   Append one dated `### YYYY-MM-DD` entry to `## Log` in the format gm-02 used: `Commits:`
   (`git log --oneline <base>..HEAD`, one `- ` line each, or `- (none)`), `Notes:` with the
   contents of `runs/<id>/notes.md` when it exists and is non-empty, the `--verify` line
   (default `Verify: not run`), and `Independent review: <--review>` (default `not recorded`;
   `land --goal`'s `_log_facts` reads this line); with `--blocked` also `Blocked: <reason>`.
   Set Status (`done` or `blocked: <reason>`), `git add` the directive file and the goal file if
   it is modified, and make exactly one commit `<id>: record results` or `<id>: blocked` with
   trailer `Directive: <id>`. Clear the marker. Print the commit hash.
4. `agents/implementer.md` and `skills/directive/SKILL.md`: state the rules: commit only when the
   step changed tracked files (code, docs, data, configs); a step that only reproduces, measures
   or inspects appends its findings to `runs/<id>/notes.md` and does not commit; never edit the
   directive's Status or Log by hand (`friday start` commits nothing, `friday finish` writes the
   record in one commit); every commit contains `Directive: <id>`. The implementer reports
   `commit: ""` when it made none. SKILL.md: the lifecycle (`approved` in the file while running,
   running shown from the marker) and the `finish` arguments.
5. Tests in `tests/test_friday.py`: update `test_cli_lifecycle`; `start` leaves the directive file
   and `git log` unchanged and stores base in the marker; `status` shows `running@` from the
   marker; `finish --verify ... --review ...` with a notes file and two code commits writes one
   Log entry containing the notes, both commit lines, the Verify line and the review line, sets
   `done`, adds exactly one commit (`<id>: record results`, trailer present) that includes the
   goal file's running flip; `finish` refuses with an uncommitted change to another tracked file;
   `finish --blocked` writes `Blocked:` and `blocked: <reason>` in one `<id>: blocked` commit;
   the warning when `runs/` is not ignored.
