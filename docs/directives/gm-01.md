## Goal
`lib/friday_core.py` holds the one definition of the goal file (`docs/goals/<goal>.md`) and the
directive file formats. `friday check` reports errors (block) and warnings (report) for one
directive, one goal or the whole repo; `friday parse ... --json` gives the workflow a parsed
directive or goal; a PostToolUse hook feeds a file's errors back to the model as soon as it edits
it. Every rule below has a test in `tests/test_friday.py`, and this repo's own goals and
directives pass `friday check --all`.

## Steps
1. [heavy] In `lib/friday_core.py`, add `parse_goal(text)`, `parse_directive_full(text)` and
   `validate_goal(gid, text)`, `validate_directive(did, text)`, each returning a list of
   `Issue(level: "error"|"warning", path, line, message)`. Keep `parse_directive` working for its
   current callers (hooks, `start`, `verify`). Heavy because: this is the single definition of both
   formats every other part reads; the error/warning boundary and the parsed shape are an API.
   Directive rules (errors unless marked):
   - First line `# <id>: <title>`; `<id>` equals the filename stem and matches `ID_RE`.
   - Header lines (before the first `##`): `Status`, `Goal`, `Node`, `Deliverable`, `Verify`,
     `Hardware` exactly once each; `Land` at most once (default `goal`). Any other `Key:` header
     line is a warning.
   - Status: `proposed` | `approved` | `running@<host>` | `done` | `blocked: <reason>` (reason
     non-empty). Node: `any` | `tag:<x>` | `host:<x>`. Deliverable: `code` | `doc` | `slides` |
     `external`. Land: `goal` | `pr` | `none`. Goal: a goal name (`^[a-z0-9][a-z0-9-]*$`).
   - Verify non-empty for code, doc, slides; for external it must be `none` and Land must be `none`.
   - Sections `## Goal`, `## Steps`, `## Out of scope`, `## Log` all present, once each, in that
     order. `## Acceptance` is optional, at most once, before `## Log`; required and with at least
     one `- ` bullet for doc, slides, external. Any other `##` section (e.g. `## Background`) is
     allowed before `## Log`.
   - Steps are a numbered list `1.` .. `n.` with no gaps; continuation lines are indented. A step
     containing `[heavy]` also contains `Heavy because:`.
   Goal file rules (errors unless marked):
   - First line `# <goal>: <title>`; `<goal>` equals the filename stem and matches the goal name
     pattern; it must not match `ID_RE` (so `friday/<goal>` never collides with `friday/<id>`).
   - Header lines `Status`, `Base`, `Land` exactly once each. Status: `proposed` | `approved` |
     `running` | `done` | `blocked: <reason>`. Base non-empty. Land: `pr` | `none`.
   - Sections `## Goal`, `## Directives`, `## Log`, once each, in that order. `## Directives` is a
     numbered list `1.` .. `n.`; each item starts with a directive id, optionally followed by
     `: <text>`. An id listed twice is an error.
2. Add `check_repo(root, directive=None, goal=None)` returning issues for the scope, with the
   cross-checks: a directive's Goal file exists and lists it; every id a goal lists has a directive
   file; a directive listed by a goal names that goal; warnings: a directive is `done` while an
   earlier one in its goal is not, and a directive is `approved` while its goal is `proposed`.
   `README.md` and `TEMPLATE.md` in either folder are skipped.
3. In `bin/friday`, add `check [<id> | --goal <g> | --all]` (no argument = `--all`): print one line
   per issue, `<level>: <path>:<line>: <message>`, then a summary; exit 1 if any error, else 0.
   Add `parse <id> --json` and `parse --goal <g> --json`. The directive JSON has: id, title,
   status, goal, base (the goal's Base, or null), node, deliverable, land, verify, hardware,
   steps `[{n, text, heavy}]`, acceptance `[str]`, goal_directives `[{id, status}]` (in goal
   order), position (1-based index in the goal), errors `[str]`, warnings `[str]`. The goal JSON
   has: goal, title, status, base, land, directives `[{id, status, deliverable, land, title}]`,
   errors, warnings. Exit 1 (JSON still printed) when errors is non-empty, 2 when the file does
   not exist. Add both commands to the docstring.
4. Add a PostToolUse hook: `hooks/hooks.json` entry with matcher `Write|Edit|MultiEdit` (MultiEdit
   is gone from current Claude Code; keeping it in the alternation is harmless) running
   `friday_hook.py posttool`. Input on stdin: `tool_name`, `tool_input.file_path` (absolute),
   `cwd`. When the file is `<repo>/docs/goals/*.md` or `<repo>/docs/directives/*.md` and not
   `README.md`/`TEMPLATE.md`, run that one file's own validation (no cross-checks, so planning can
   write the goal before its directives). On errors, print them to stderr and exit 2 (Claude Code
   shows PostToolUse exit-2 stderr to the model; the edit itself has already happened). Clean or
   warnings only: no output, exit 0. Any exception: exit 0 (fail open), like the other hooks.
5. Migrate this repo to the format: add Goal/Deliverable/Land headers to `fleet-01..03`
   (`Goal: fleet`, `Deliverable: code`; `Land: pr` for fleet-01, which landed as PR #1, `Land:
   goal` for 02 and 03), and add `docs/goals/fleet.md` (`Status: approved`, `Base: v1`,
   `Land: pr`, Directives fleet-01..03 with their titles). Change nothing else in those
   directives. Add `runs/` to `.gitignore`. `./bin/friday check --all` exits 0.
6. Tests in `tests/test_friday.py`: a minimal valid directive and goal fixture, then one
   parametrized case per rule in steps 1-2 (mutate the fixture, assert the level and a message
   substring), covering every error and every warning; `parse --json` for a directive and a goal
   (field values, exit codes 0/1/2); `check` exit codes and output format; the hook: clean edit
   silent with exit 0, broken directive exit 2 with the error on stderr, README.md and files
   outside `docs/` ignored, garbage stdin exit 0.
