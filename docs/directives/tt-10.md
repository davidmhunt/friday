# tt-10: Plan edits made while a directive runs are shown to its review

## Goal
With plans on the goal branch (tt-04), `friday commits <id>` drops every plan-only commit (files
only under docs/goals/, docs/directives/ or .claude/settings.json), so an agent that edits its own
directive's Verify, steps, Rules or Allowed commands during the run is invisible to the review.
That happened in tt-09 (a fix agent rewrote the Verify line). After this directive `friday start
<id>` records the HEAD it starts from in `runs/<id>/start` (untracked; written only when absent,
so a restart keeps the first point). Plan-only commits that are ancestors of that point are the
plan and stay excluded; when the file is absent, all plan-only commits are excluded (older runs).
Plan-only commits after it are listed as `plan <sha> <subject>` lines (`plan` in `--json`), with
or without a trailer. The two review prompts in workflows/execute.js say a `plan` line is a plan
edit made after the directive started and is a gap if it changes this directive's goal, steps,
Verify, Rules or Allowed commands. `friday finish` keeps listing only own commits in the Log.

## Steps
1. bin/friday `cmd_start` writes `runs/<id>/start`; lib/friday_core.py `directive_commits` returns
   `plan` as above (plan-only keeps the .claude/settings.json case); `friday commits` prints and
   `--json` returns it.
2. workflows/execute.js review and second-review prompts: the `plan` line rule.
3. docs/spec.md section 6 "A directive's change set" and the `friday commits` row; tests/test_spec.py
   stays green. CHANGELOG `Unreleased` line.
4. Tests: a plan commit (goal file plus .claude/settings.json, trailers for two directives) before
   start is excluded; a trailered edit to the directive after start is a `plan` line; an untrailered
   one is too; a restart keeps `runs/<id>/start`; absent file excludes all plan-only commits; a code
   commit with the trailer is still own work; an execute.js test checks both review prompts.

## Out of scope
- Blocking plan edits in the hook.
