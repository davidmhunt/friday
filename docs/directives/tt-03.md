# tt-03: `friday nodes --setup <node>` reports each worker prerequisite with its fix, also for a target being promoted (fixes #23)
Status: approved

Node: any
Deliverable: code
Land: goal
Verify: uv run --with pytest pytest -q tests/test_docs.py tests/test_spec.py && uv run --with pytest pytest -q && claude plugin validate .
Hardware: none

## Goal
Promoting a robot to a worker is cheap because friday names every missing piece. `friday nodes
--check` additionally probes `uv`, `gh auth status` (push credentials for `friday land`), and
whether `claude` is signed in (`claude auth status`, reading `loggedIn`), each with a fix line.
`friday nodes --setup <node>` first runs the same prerequisite probe and prints one line per
prerequisite (ok, or missing with its fix) before it changes anything. For a node whose role is
`target` it no longer just refuses: it prints the prerequisites and the `nodes.toml` change that
makes it a worker (`role = "worker"`, `repos`, `plugin_dir`), changes nothing on the node, and
exits 1 so the user edits the registry and re-runs it. Items a person must do (sign in,
`gh auth login`, accept trust) are reported, never done.

## Steps
1. bin/friday `probe_script`/`check_node`: probe `uv` (on PATH or `~/.local/bin`), `gh auth status`
   (ok / gh missing / not logged in) and `claude auth status` (`loggedIn` true / false / unknown);
   add fix lines (install uv, pointing at https://docs.astral.sh/uv/getting-started/installation/;
   run `gh auth login` on the node; run `claude` and `/login` on the node). The probe also runs
   for target nodes when asked by `--setup`.
2. bin/friday `cmd_nodes_setup`: run the probe first and print `prerequisites:` with one line each;
   for a target, print the prerequisites and the registry edit, change nothing, exit 1. For a
   worker or master, continue to the settings step as today after printing them (missing
   person-only items do not stop the settings change).
3. docs/fleet.md (Setup, and the promotion paragraph of the "Targets and workers" section) and
   docs/spec.md (`friday nodes --setup` and `--check` rows) updated; tests/test_spec.py stays
   green. CHANGELOG `Unreleased` entry naming #23.
4. Tests with a fake ssh (as the existing nodes tests do): `--check` reports missing uv, gh not
   logged in and claude not signed in with fix lines; `--setup` on a target prints the
   prerequisites and the registry edit, exits 1 and runs no settings script; `--setup` on a
   worker prints the prerequisites before the settings prompt.

## Out of scope
- Installing anything on the node or signing in for the user.
- A project's native runtime (ROS etc.): that stays the project's own check.
